## The right way to make agents robust and wise

Do **not** add only production/design skills.

A robust geotechnical agent needs three layers in every field:

1. **Interpretation skills**
   turn messy field/lab/input data into structured engineering inputs.

2. **Design or simulation skills**
   run deterministic calculations, option screening, and staged workflows.

3. **Reviewer or judgment skills**
   challenge assumptions, audit safety factors, detect parameter conflicts, and curate evidence into the case file.

That third layer is what makes the agent “wise,” not just capable. It fits geotechCLI especially well because the repo already has case-file, artifact, evidence, and report infrastructure that can hold structured review outputs.

## Naming pattern I recommend

To keep the skill library consistent, use these suffixes:

* `...-screening` for early-stage design or option narrowing
* `...-synthesis` for interpretation and input fusion
* `...-review` for expert QA and decision critique
* `...-audit` for standards/safety-factor checking
* `...-observational-control` for monitoring-trigger workflows
* `...-register` for structured uncertainty/risk/evidence capture

That naming pattern makes it obvious whether a skill is:

* interpretive
* computational
* judgmental
